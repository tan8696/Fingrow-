1. PROJECT EXECUTIVE SUMMARY & OBJECTIVES
====================================================================================================
FinGrow Advisory is an institutional-grade, multilingual rural micro-enterprise feasibility analysis,
credit structuring, and agro-climatic risk advisory platform built for the Smart India Hackathon (SIH).

THE CORE PROBLEM:
Prospective rural micro-entrepreneurs and marginal farmers across India face critical barriers:
1. Inability to navigate complex government concessional lending schemes (NABARD, PMEGP, SCA/CA).
2. Risk of starting saturated businesses without knowing local market competition.
3. Language barriers, as institutional banking guidelines and appraisal forms are predominantly in English.
4. Agricultural vulnerability to sudden climate shocks, unseasonal rainfall, and pest attacks.
5. Inability to communicate via traditional keyboards or complex graphical interfaces.

THE FINGROW SOLUTION:
The platform allows rural entrepreneurs to provide three basic inputs:
- Geographic Location (Village, Gram Panchayat, Block, District, State)
- Available Margin Capital (The user's own cash contribution in Rupees)
- Proposed Business Category (e.g., Organic Poultry, Dairy, Flour Mill, Cold Storage, Grocery)

Within seconds, the platform executes a synchronized pipeline:
1. Normalizes the location to geographic GPS coordinates.
2. Fires a spatial radar query across OpenStreetMap to detect active local competitors within 5-10 km.
3. Applies deterministic financial arithmetic (zero AI hallucination) to size project costs and amortize loans.
4. Prompts a strictly bounded Large Language Model (Groq / Gemini) to draft hyper-local SWOT, pricing,
   and supply chain advice using the real competitor count as immutable ground truth.
5. Translates the analysis into regional Indian languages (Hindi, Marathi, Bengali, Telugu, etc.).
6. Generates a bank-ready, vector PDF Feasibility Report with official audit tables.
7. Empowers the user to operate the entire portal through an Indian-accented bilingual Voice Assistant.

4. DEEP-DIVE INTO CORE BUSINESS LOGICS & MATHEMATICAL FORMULAS
====================================================================================================

4.1 THE 10% MARGIN CAPITAL & 90% LOAN SIZING MODEL
--------------------------------------------------
Under national rural micro-enterprise guidelines (NABARD, PMEGP, State Credit Agencies), the prospective
entrepreneur is required to contribute a minimum equity stake of 10% (Margin Capital). The institutional
lender provides 90% debt financing.

Mathematical Formulation:
  Margin Capital (M) = Provided by user (₹)
  Margin Percentage  = 10% (0.10)
  Debt Percentage    = 90% (0.90)

  Total Project Cost (P_cost) = M / 0.10
  Bank Loan Amount   (L)      = P_cost * 0.90 = (M / 0.10) * 0.90 = M * 9.0

Example:
  User enters Margin Capital = ₹50,000
  Total Project Cost = ₹50,000 / 0.10 = ₹5,00,000
  Sanctioned Loan    = ₹5,00,000 * 0.90 = ₹4,50,000

4.2 GOVERNMENT SCHEME ROUTING GATES & ELIGIBILITY BOUNDS
--------------------------------------------------------
In `backend/app/core/calculator.py`, routing is completely deterministic:

  Condition 1: Margin Capital <= 0
    -> ACTION: REJECT with ValueError("Margin capital must be positive.")

  Condition 2: Total Project Cost <= ₹1,40,000 (Margin Capital <= ₹14,000)
    -> ROUTE TO: "Micro Finance Scheme"
    -> Annual Interest Rate : 6.50% p.a.
    -> Loan Tenure          : 36 Months (3 Years / 12 Quarters)
    -> Moratorium (Grace)   : 3 Months (1 Quarter)
    -> Repayment Unit       : Quarterly Reducing Balance

  Condition 3: ₹1,40,000 < Total Project Cost <= ₹50,00,000 (₹14,000 < Margin <= ₹5,00,000)
    -> ROUTE TO: "Term Loan Scheme"
    -> Annual Interest Rate : 8.00% p.a. (Eligible for subvention down to 7.00%)
    -> Loan Tenure          : 84 Months (7 Years / 28 Quarters)
    -> Moratorium (Grace)   : 6 Months (2 Quarters)
    -> Repayment Unit       : Quarterly Reducing Balance

  Condition 4: Total Project Cost > ₹50,00,000 (Margin Capital > ₹5,00,000)
    -> ACTION: REJECT with SchemeError("Project cost exceeds maximum limit of ₹50,00,000.")

4.3 MORATORIUM (GRACE PERIOD) MECHANICS
---------------------------------------
Micro-enterprises (such as livestock, dairy, poultry, crops) require gestation time before generating revenue.
During the Moratorium:
- Principal Repayment = ₹0.00
- Borrower pays ONLY the accrued interest for that period.
- Amortization begins strictly after the moratorium ends.

4.4 REDUCING-BALANCE AMORTIZATION FORMULAS
------------------------------------------

A) Quarterly Amortization (Report Engine — `amortization.py`):
   Total Quarters (Q_total) = Tenure Months / 3
   Moratorium Quarters (Q_mora) = Moratorium Months / 3
   Repayment Quarters (Q_repay) = Q_total - Q_mora

   Quarterly Interest Rate:
     r_q = (Annual Interest Rate / 100) / 4

   During Moratorium (Quarters 1 to Q_mora):
     Interest Payment  = Loan Amount * r_q
     Principal Payment = 0
     Total Payment     = Interest Payment
     Closing Balance   = Opening Balance = Loan Amount

   Post-Moratorium (Quarters Q_mora + 1 to Q_total):
     Quarterly EMI = L * [ r_q * (1 + r_q)^Q_repay ] / [ (1 + r_q)^Q_repay - 1 ]
     For each quarter:
       Interest Component  = Opening Balance * r_q
       Principal Component = Quarterly EMI - Interest Component
       Closing Balance     = Opening Balance - Principal Component
       (On the final quarter, Principal Component absorbs any rounding delta to ensure Closing Balance = 0.00)

B) Monthly Amortization (Loan Approval & Repayment Tracking — `loan_schedule.py`):
   Monthly Interest Rate:
     r_m = (Annual Interest Rate / 100) / 12

   Monthly EMI:
     EMI = L * [ r_m * (1 + r_m)^n ] / [ (1 + r_m)^n - 1 ]
     where n = Tenure Months

4.5 GOVERNMENT CAPITAL SUBSIDY FORMULA & CAPPING LOGIC
------------------------------------------------------
Under priority sector agricultural initiatives (e.g., Agriculture Infrastructure Fund - AIF):
  Subsidy Rate = 25% of Total Project Cost
  Subsidy Cap  = ₹5,00,000 (Maximum Backend Credit)

  Subsidy Amount = MIN(Project Cost * 0.25, 500000)

Example 1: Project Cost = ₹1,20,000
  Subsidy = MIN(120000 * 0.25, 500000) = MIN(30000, 500000) = ₹30,000

Example 2: Project Cost = ₹30,00,000
  Subsidy = MIN(3000000 * 0.25, 500000) = MIN(750000, 500000) = ₹5,00,000 (Capped)

4.6 OPENSTREETMAP COMPETITOR DENSITY CLASSIFICATION ALGORITHM
-------------------------------------------------------------
In `backend/app/core/osm_fetcher.py`, the Overpass API executes an around-radius spatial scan:
  Count = Number of matching POI nodes and ways within radius_km (default 10 km).

Classification Rules:
  - Count == 0         : "None (First-Mover Opportunity)"
  - 1 <= Count <= 3    : "Sparse"
  - 4 <= Count <= 10   : "Moderate"
  - Count > 10         : "Dense (Saturated)"

4.7 MARKET VIABILITY SCORE (90% GREEN CIRCLE ALGORITHM)
-------------------------------------------------------
In `frontend/src/components/MarketReport.jsx`, the viability gauge is computed deterministically:
  Baseline Score = 85

  Modifier Based on Density:
    If Density is "None" or "Sparse" : Modifier = +5  -> Final = 90% (High Potential)
    If Density is "Moderate"         : Modifier = -10 -> Final = 75% (Moderate Potential)
    If Density is "Dense"            : Modifier = -20 -> Final = 65% (High Competition)

  Score Clamping:
    Viability Score = MAX(20, MIN(100, Baseline + Modifier))

4.8 DETERMINISTIC WEATHER & CROP-RISK 0-10 INDEX RULES
------------------------------------------------------
In `backend/app/core/weather.py`, risk scoring is rule-based:
  Base Score = 1

  Rule 1 (Rain Probability):
    If any day in forecast has rain probability >= 60%:
      Score += 3
      Add advisory: "Plan around incoming rain; delay irrigation and harvesting."

  Rule 2 (Humidity & Fungal Threat):
    If mean 7-day relative humidity >= 70%:
      Score += 2
      Add advisory: "Scout for pest & fungal pressure (bollworm, blight)."

  Rule 3 (Extreme Heat Stress):
    If maximum temperature >= 38°C:
      Score += 3
      Add advisory: "Heat-stress management; irrigate early morning/evening, shelter livestock."

  Rule 4 (Wind Drift):
    If maximum wind speed >= 35 km/h:
      Score += 1
      Add advisory: "Hold off on spraying; high wind causes chemical drift."

  Rule 5 (Thunderstorm Hazard):
    If any day has WMO code >= 95 (Thunderstorm):
      Score += 1
      Add advisory: "Storm watch; secure polyhouses and shade nets."

  Final Risk Score = MAX(0, MIN(10, Computed Score))
  Classification:
    0 - 2 : "Low Risk"
    3 - 5 : "Moderate Risk"
    6 - 7 : "High Risk"
    8 - 10: "Severe Risk"

4.9 PEST THREAT ESTIMATION ALGORITHM
------------------------------------
In `backend/app/core/agro.py`, pest vector outbreaks are calculated from humidity and rainfall:
  Average Humidity = Mean(relative_humidity_2m_mean across daily forecast)
  Rainy Days Count = Count(days with precipitation_sum >= 1.0 mm)

  Level 3 Alert (Pink Bollworm & Yellow Mosaic Virus):
    Trigger: Average Humidity >= 70% AND Rainy Days >= 2
    Risk Percentage: MIN(95, 35 + (Average Humidity - 70) * 4)
    Action Protocol: Deploy 5 pheromone traps/acre; release Trichogramma bactrae.

  Level 2 Watch (Stem Fly & Charcoal Rot Blight):
    Trigger: Average Humidity >= 60%
    Risk Percentage: MIN(70, 30 + (Average Humidity - 60) * 3)
    Action Protocol: Spray Chlorantraniliprole 18.5 SC @ 3 ml/10 L water; Trichoderma at stem base.

  Level 1 Low (Aphids / Thrips - Low):
    Trigger: Average Humidity < 60%
    Risk Percentage: MAX(15, 35 - (60 - Average Humidity) * 1.5)
    Action Protocol: Routine weekly scouting; keep neem-based foliar spray ready.

4.10 AGRICULTURAL SPRAY-WINDOW CLASSIFICATION RULES
---------------------------------------------------
For each daily forecast day:
  - Precipitation Probability = P_rain (%)
  - Wind Speed 10m Max        = W (km/h)
  - Weather Code              = C (WMO integer)
  - Precipitation Sum         = R (mm)

  Classification Hierarchy:
    1. AVOID SPRAY:
       If C >= 95 OR P_rain >= 85% OR (R >= 10 mm AND P_rain >= 60%)
    2. OPTIMAL SPRAY:
       If P_rain < 35% AND W < 15 km/h
    3. GOOD WINDOW:
       If P_rain < 60% AND W < 20 km/h
    4. MARGINAL:
       All other combinations.

4.11 PARAMETRIC INSURANCE TRIGGER EVALUATION & PAYOUT ESTIMATION
----------------------------------------------------------------
In `backend/app/core/agro.py`:
- Sum Insured = ₹8,50,000 across 28.5 Acres (Base Policy: PMFBY-AIC-MHA-89218)
- Payout Claim Factors:
  * Excess Rain (> 65 mm in 24h)     : 25% of Sum Insured
  * Hailstorm / High-Wind Damage     : 35% of Sum Insured
  * Prolonged Drought (> 21 dry days): 20% of Sum Insured
  * Heat Wave (> 3 days > 41°C)      : 15% of Sum Insured
  * High-Wind Lodging                : 15% of Sum Insured

- Pro-Rata Acreage Payout Formula:
  Acre Fraction = MIN(1.0, Area Acres / 28.5)
  Estimated Payout = Sum Insured * Claim Factor * Acre Fraction

  Example: Excess Rain on 14.25 Acres:
    Acre Fraction = 14.25 / 28.5 = 0.50
    Estimated Payout = ₹8,50,000 * 0.25 * 0.50 = ₹1,06,250

4.12 FAIL-SAFE GEOCODING & INTERNAL INDIAN DISTRICT GAZETTEER FALLBACK
----------------------------------------------------------------------
To ensure the platform never halts when international OpenStreetMap servers experience latency,
`backend/app/core/geocoder.py` embeds a 40-district offline Indian gazetteer covering:
- Vidarbha / Maharashtra (Akola, Nagpur, Amravati, Wardha, Yavatmal, Chandrapur, Bhandara, Gondia, etc.)
- Rest of Maharashtra (Pune, Mumbai, Nashik, Chhatrapati Sambhajinagar, Kolhapur, Solapur, Latur, etc.)
- North & Central India (Barabanki, Rampur, Lucknow, Varanasi, Jaipur, Bhopal, Indore, Patna, etc.)
If Nominatim fails or times out (> 6s), the internal gazetteer resolves coordinates instantly in 0 milliseconds.

4.13 ANTI-HALLUCINATION PROMPT ENGINEERING CONSTRAINTS
------------------------------------------------------
In `backend/app/core/advisory.py`:
- Rule 1: The model is NEVER allowed to calculate or alter financial amounts (Project Cost, Loan, EMI).
- Rule 2: Competitor figures from OSM are injected as immutable ground truth.
- Rule 3: The model is strictly instructed: "Do NOT invent demographic statistics, population figures,
  or income data."
- Rule 4: Output is validated via Pydantic; if schema parsing fails, an automated single-retry is executed.

5. VOICE ASSISTANCE ARCHITECTURE (CLIENT-SIDE & WEBSOCKET STREAMING)
====================================================================================================
FinGrow features a dual-layer voice architecture designed for high availability, Indian accents,
and instant UI responsiveness.

5.1 CLIENT-SIDE WEB SPEECH RECOGNITION (BROWSER-NATIVE)
-------------------------------------------------------
- Component: `frontend/src/components/FloatingVoiceAgent.jsx` & `hooks/useVoiceAndLocation.js`
- API Used: `window.SpeechRecognition || window.webkitSpeechRecognition`
- Configuration:
  * `recognition.continuous = true` (Keeps mic stream open during conversational pauses)
  * `recognition.interimResults = true` (Displays live words as the farmer speaks)
  * `recognition.lang = 'en-IN'` (Configured for Indian English accents and Hinglish pronunciations)
- Stream Resolution:
  * Interim results are appended with an ellipsis ("…") to provide visual feedback.
  * Finalized transcripts are parsed by the intent routing engine.

5.2 INTENT CLASSIFICATION, PATTERN MATCHING & "VOICE SURFING"
-------------------------------------------------------------
The user can navigate the entire application by voice without clicking a single button:

1. Navigation Intents:
   - User says: "Open scheme calculator" / "calculate loan"
     -> Calls `onNavigate('calculator')`
     -> Regex match: `\b(\d{4,})\b`
     -> If user says "Open calculator with 100000", it automatically parses ₹1,00,000 and sets the slider!
   - User says: "Show feasibility report" / "business plan"
     -> Calls `onNavigate('feasibility')`
   - User says: "Check my loan history" / "my active loans"
     -> Calls `onNavigate('history')`
   - User says: "Show mandi rates" / "market prices"
     -> Calls `onNavigate('market')`
   - User says: "Go to dashboard" / "take me home"
     -> Calls `onNavigate('dashboard')`

2. Modal Interaction & Accessibility:
   - Dismissible via UI close button, clicking the backdrop, or pressing the `Escape` key.
   - Global event listeners (`open-voice-agent`, `open-chat-support`, `open-chat-with`) allow any card in the
     app to open the voice assistant with prefilled queries.

5.3 SPEECH SYNTHESIS (TTS) & ACOUSTIC CUSTOMIZATION
---------------------------------------------------
- API Used: `window.speechSynthesis` & `SpeechSynthesisUtterance`
- Configuration:
  * Language: `'en-IN'`
  * Speech Rate: `1.0` (Natural conversational cadence)
  * Pitch: `1.0`
  * Prior to speaking, `synth.cancel()` is called to flush any queued utterances and prevent voice stutter.

5.4 BUILT-IN OFFLINE DOMAIN KNOWLEDGE BASE
------------------------------------------
If the user asks an informational question (rather than a navigation command), the assistant consults an
embedded expert rural knowledge base (`KNOWLEDGE_BASE`):
- Keyword "subsidy" -> Explains Maha-Krushi 25% capital subsidy and NABARD priority norms.
- Keyword "poultry" -> Explains Vidarbha organic poultry viability (85% score, 18-month break-even).
- Keyword "interest" / "emi" -> Explains priority sector 7.00% p.a. terms and 6-month moratorium.
- Keyword "eligibility" -> Explains 15% equity margin, 7/12 land records, and Udyam registration.
- Keyword "market" -> Points to live APMC organic commodity rates.

5.5 SERVER-SIDE WEBSOCKET AUDIO STREAMING (`/ws/voice`)
-------------------------------------------------------
- Backend Skill Location: `backend/agent/skills/websocket-voice-stream/voice_server.py`
- Protocol: Asynchronous Full-Duplex WebSocket (`ws://localhost:8000/ws/voice`)
- Pipeline:
  1. Frontend captures binary audio chunks using the browser `MediaRecorder` API.
  2. Binary audio frames are transmitted over the open WebSocket.
  3. Server-side Regional STT Integration: Transcribes raw audio frames to text (integrates Sarvam AI /
     Bhashini speech models).
  4. Instant Transcript Broadcast: Emits `{"transcript": "..."}` back to the client for immediate UI rendering.
  5. LLM Business Logic Processing: Evaluates the transcript against business rules.
  6. Server-side Regional TTS Integration: Synthesizes high-fidelity regional Indian voice audio bytes.
  7. Audio Streaming: Server sends binary audio back to the frontend for zero-latency audio playback.

7. DATABASE ARCHITECTURE & SQLITE SCHEMAS
====================================================================================================
The backend employs an embedded, zero-maintenance SQLite architecture across four database files in `backend/`:

1. `sessions.db` (`session_store.py`):
   Stores generated feasibility reports so they can be re-accessed and exported to PDF:
   ```sql
   CREATE TABLE IF NOT EXISTS sessions (
       session_id  TEXT PRIMARY KEY,
       report_json TEXT NOT NULL,
       created_at  TEXT NOT NULL DEFAULT (datetime('now'))
   );
   ```

2. `loans.db` (`loan_store.py`):
   Stores loan applications, approval metadata, repayment ledgers, and payment history:
   ```sql
   CREATE TABLE IF NOT EXISTS loan_applications (
       application_id   TEXT PRIMARY KEY,
       application_json TEXT NOT NULL,
       created_at       TEXT NOT NULL DEFAULT (datetime('now'))
   );
   ```

3. `harvest.db` (`harvest_store.py`):
   Stores agricultural harvest records and realized commodity revenues:
   ```sql
   CREATE TABLE IF NOT EXISTS harvest_lots (
       harvest_id   TEXT PRIMARY KEY,
       harvest_json TEXT NOT NULL,
       created_at   TEXT NOT NULL DEFAULT (datetime('now'))
   );
   ```

4. `advisory.db` (`advisory_store.py`):
   Stores parametric insurance claims and field spray reminders:
   ```sql
   CREATE TABLE IF NOT EXISTS insurance_claims (
       claim_id    TEXT PRIMARY KEY,
       claim_json  TEXT NOT NULL,
       created_at  TEXT NOT NULL DEFAULT (datetime('now'))
   );

   CREATE TABLE IF NOT EXISTS field_reminders (
       reminder_id   TEXT PRIMARY KEY,
       reminder_json TEXT NOT NULL,
       created_at    TEXT NOT NULL DEFAULT (datetime('now'))
   );
   ```

8.1 ENVIRONMENT CONFIGURATION (`backend/.env`)
----------------------------------------------
To enable LLM generation, set your API key in `backend/.env`:
```env
# Required for AI Feasibility Report Generation:
GROQ_API_KEY=your_groq_api_key_here

# Optional model selection (default: openai/gpt-oss-120b or llama-3.3-70b-versatile):
GROQ_MODEL=openai/gpt-oss-120b

# Optional database paths (defaults to local SQLite files in backend/):
SESSION_DB_PATH=sessions.db
LOANS_DB_PATH=loans.db
HARVEST_DB_PATH=harvest.db
ADVISORY_DB_PATH=advisory.db

# Optional CORS origins (defaults to Vite dev server):
CORS_ORIGINS=http://localhost:5173,http://localhost:3000
```
Note: The Standalone Financial Calculator (`/api/calculate`) and Weather module work completely
WITHOUT any external API keys!

8.2 LOCAL EXECUTION INSTRUCTIONS
--------------------------------
Step 1: Start the Backend (FastAPI)
  cd backend
  python -m venv venv
  # Windows:
  venv\Scripts\activate
  # Linux / macOS:
  source venv/bin/activate
  pip install -r requirements.txt
  uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

  Interactive Swagger Documentation: http://localhost:8000/docs

Step 2: Start the Frontend (React + Vite)
  cd frontend
  npm install
  npm run dev

  Open Web Application: http://localhost:5173

Step 3: Run Automated Test Suite
  cd backend
  python -m pytest tests -v
  (Executes 131 automated unit and integration tests across financial math, geocoding, and APIs).
